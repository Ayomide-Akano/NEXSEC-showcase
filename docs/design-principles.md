# Design principles

1. **Understand before acting.** A system should not defend what it does not understand.
2. **Authorize before controlling.** Finding a gateway does not grant control of it. Authorization is a separate, recorded step.
3. **Validate before enforcing.** Confirm what an integration can actually do before relying on it.
4. **Represent reality, not fabricate capability.** If no adapter exists, say so ("awaiting adapter").
5. **Observation-only first run.** Newly found assets are inventoried and classified, never automatically blocked.
6. **Explain every important decision.** What happened, why, which evidence, which authorization, which integration.
7. **Controlled autonomy.** More autonomy only comes with stronger visibility, policy controls, verification, and auditing.
8. **Protect the protector.** A security platform is a high-value target and must be hardened itself.
9. **Conservative classification.** Use evidence and confidence levels instead of false certainty.
10. **Trustworthy automation, not maximum automation.**
